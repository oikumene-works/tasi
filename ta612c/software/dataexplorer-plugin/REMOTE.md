# Remote repository readiness

This repository is prepared for a later GitHub, GitLab or other Git remote. No
remote is configured and nothing has been published.

## Recommended first publication

Start with a private remote unless the decoded temperature fixtures and project
history have been deliberately reviewed for public release. Physical meter OSD
evidence, accepted binaries, logs and downloaded dependencies are already under
the ignored `local/` tree and will not be included by a normal Git push.

The tracked `test/fixtures/` directory is intentional: its CSV and OSD files are
required regression inputs. Review those files before changing a remote from
private to public. The source is GPL-3.0-or-later; preserve `COPYING` and the
existing attribution.

## Connect an empty remote

Create an empty repository without an autogenerated README, license or
`.gitignore`, then run:

```sh
git remote add origin <ssh-or-https-url>
git remote -v
git push -u origin main
git push origin partial-probes-accepted-2026-09-15
```

Before every first push to a new destination, inspect:

```sh
git status --short --ignored
git ls-files
git remote -v
```

Do not place access tokens in a remote URL, repository file or command transcript.
Use the hosting provider's credential manager or SSH configuration.
